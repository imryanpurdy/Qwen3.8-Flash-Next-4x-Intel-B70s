- EVERY write gets a read-back with the tool that observes the effect — never trust exit codes or success-looking output alone: git add → `git status --short` shows staged A/M lines; sed → grep the exact changed line (check the anchor is actually a LINE START — vars inside quoted strings are not); scp/put → md5sum both ends; pip install → `pip show`; docker commit → `docker images` + entrypoint inspect.

**Flag lessons (hard-won, do not regress):**

- No `--warmup`: pre-reserves worst-case compute pool → first real request OOMs SYCL pool.

**Ops traps (burned us):**
- `docker run -e LD_LIBRARY_PATH=...` REPLACES the image's env (does not append) — DLE's own LD_LIBRARY_PATH carries its SYCL runtime trees; overriding it re-creates the 0-adapters disease + cascading missing libs (libsvml, libiomp5, libsycl.so.9, libur_loader.so.0). Never set it on this image; if a lib from /cache is needed, use an ldconfig wrapper (`echo dir > /etc/ld.so.conf.d/x.conf && ldconfig && exec "$@"`) so system dirs keep priority. Also never copy UR loader/adapter/libsycl .so files out of the compiler tree into a shadow dir — they poison device init.
- Fresh build dir = UI provisioning tar pit: no HF network in build containers → ui-embed step tries to fetch assets and fails; that embed tool also fails to link under icx (missing libstdc++ in its link line). Fixes that work: copy the prior build dir's `tools/ui/` contents incl. hidden `.ui-stamp` (root-owned — copy via docker) and `dist/`, `touch` the copied assets newer than sources, or configure with `-DLLAMA_BUILD_UI=OFF` (API-only serving is fine without it). If CMakeCache came from a different mount path, sed CMAKE_HOME_DIRECTORY/CMakeLists.txt paths (`/src` → current).
- `xpu-smi` exists on jobe host as bonz (no docker needed): `xpu-smi discovery` (device→BDF map, Device State), `xpu-smi stats -d N` (clocks/power/mem). Idle cards sit at 400MHz — idle samples prove nothing; sample clocks DURING a bench to check boost (healthy B70: 400→2050–2800).
- `docker run` for the server MUST publish the port (`-p 8021:8021`) — health checks from the host silently fail otherwise while the container looks perfectly alive.
- llama-server `/completion` honors natural EOS: a tidy encyclopedic prompt ends at ~110 tok regardless of n_predict — bench with `ignore_eos:true` and an open-ended prompt, else you measure 1-token runs.
- `git apply --3way` is ATOMIC: rc=1 on one file rolls back all "applied cleanly" narration. Use `--reject` for partial landing (and `--reject` + `--3way` are mutually exclusive).
- plink `pkill -f X` dies when X appears in the remote command line itself — write a launcher script or use `[x]` bracket trick.
- nohup+& directly in plink hangs the session; use `setsid nohup ... < /dev/null &` inside a script file.
- HF GGUF shard names are 5-digit zero-padded (`00001-of-00033`); `seq -w` gives 2 digits — prefix `000`.
- jobe: root is LVM on the 238GB NVMe (106GB free); `sda` 931GB is `zfs_member`, unmounted, sudo password unknown; docker images prune freed nothing (55 "dangling" = shared intermediate layers; real reclaim = dead containers).
